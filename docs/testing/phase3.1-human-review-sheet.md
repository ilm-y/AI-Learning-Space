## 两者不是同一层面的两件事

TLB 缓存的是**翻译结果**（页表项），并非**页本身**。所以，TLB 里有没有这一条，回答的是「这次地址翻译能不能直接查到」；缺页回答的是「你要访问的那个页，现在到底在不在物理内存里」。这两个问题分别由不同的东西回答：一个查 TLB，一个查页表项里的 present 位和权限位。

## 三条岔路

**1. 页在内存，只是 TLB 里没这条。** 这是最常见的情况。处理方式就是走一遍页表、把结果填回 TLB、重试指令。没有异常、没有磁盘 I/O，程序完全感知不到。所以「TLB miss 之后是否一定触发缺页」的答案是：不一定，而且多数情况下不会。

这里有个实现差异值得知道：x86 这类硬件 page walk 的架构，TLB miss 由硬件自己查页表；MIPS 这类软件管理 TLB 的架构，TLB miss 会陷入内核，由 OS 的 TLB-miss 处理程序来填。但后者仍然只是「填 TLB」，和缺页是两码事：它不读磁盘，也不做置换。具体行为以各架构手册为准。

**2. PTE 的 present 位是 0。** 页不在内存，这才是缺页。这时才轮到 OS：找物理页框、从磁盘或交换区读入、更新 PTE、返回后重试指令。重试翻译时 TLB 里仍然没有，再走一次，这次 PTE 有效，填进 TLB 就过去了。

**3. 权限不符。** 页在内存，但这次访问不被允许（写只读页、用户态访问内核页）。这也是异常，但它不是「页不在内存」，通常不需要读磁盘。

## 缺页和置换的边界

「缺页就是要去磁盘把页读进来」作为典型情形成立，边界在两点：

- 缺页是**触发事件**，置换只是缺页处理里的一个**分支**。OS 收到缺页后先看有没有空闲页框：有，就直接分配、读入，根本不涉及置换；没有空闲页框，才需要挑牺牲页，这一步才是页面置换，脏页还得先写回。LRU、Clock 这些算法只在「没有空闲页框」这条分支上才有意义。
- 也不是所有缺页都要读磁盘：匿名页首次访问可以映射到全零页、写时复制可以直接复用父进程的页、栈增长只是扩一下 VMA。这些都会触发缺页异常，但没有磁盘 I/O。

## 关键：置换只是缺页处理流程中的一个分支

你的说法「缺页就是要去磁盘把页读进来」本身没错，但它漏掉了「读进哪里」以及「位置不够时怎么办」这两个环节。把整条因果链展开：

​```
CPU 发出虚拟地址 VA
      │
      ▼
   MMU 用 VA 的页号查页表
      │
      ├─ 页表项 valid=1 ──► 拿到物理帧号 → 拼出 PA → 正常访问
      │
      └─ 页表项 valid=0 ──► 触发缺页异常
                              │
                              ▼
                    CPU 陷入内核，跳 OS 缺页处理程序
                              │
                              ▼
                  ① OS 检查：这个地址合法吗？
                       否 → 非法访问（如段错误），杀进程
                       是 ↓
                  ② 有没有空闲帧？
                       ├─ 有 ──► 直接用（第一次缺页通常走这里，不置换）
                       └─ 没有 ──► ③ 页面置换
                                     ├─ 选一个牺牲页 victim
                                     ├─ 是脏页？→ 先写回磁盘
                                     ├─ 清它的 valid 位 / 刷 TLB
                                     └─ 腾出这个帧
                              │
                              ▼
                  ④ 从磁盘读「缺的那一页」进帧
                              │
                              ▼
                  ⑤ 更新页表项：帧号 + valid=1（必要时刷 TLB）
                              │
                              ▼
                  ⑥ 返回用户态，重新执行那条缺页的指令
​```

要点是：**置换是缺页处理程序内部的一个可选分支，并非缺页处理的别名**。只有「没有空闲帧」时才会走③；进程刚开始运行、还有空闲帧时，②就直接结束了。

## 三个具体分叉：检查你的推理是否在这些地方偏离

**1. 被换出的页和被换入的页是两个不同对象。**
置换的候选集是「此刻正占着物理帧的页」，也就是已在内存中的页；你要读进来的是那个 valid=0 的页。常见混淆是以为「置换就是把我缺的页换出去」，而实际上是把别的页赶走，给缺的页腾位置。

**2. 脏页必须先写回。**
选中的牺牲页如果被修改过（脏位/修改位=1），换出前必须写回磁盘，否则数据丢失；干净页可以直接丢弃。这决定了置换的开销：有时一次缺页要两次磁盘 I/O（写回旧页 + 读入新页）。

**3. 触发者和处理者要分开。**
MMU 只做两件事：地址翻译、发现 valid=0 并触发异常。它不读磁盘、不选牺牲页、不改页表项。选 victim、写回脏页、发起磁盘 I/O、更新页表，全是 OS 的缺页处理程序在内核里做的。硬件负责发现和陷入，OS 负责修复。

顺带划清一条容易混淆的边界：**缺页不等于 TLB miss**。TLB miss 是快表没命中，页表里可能明明有这项，查一次页表填上就行，不陷入缺页处理；只有页表项 valid=0 才升级为缺页。至于 TLB miss 是由硬件遍历页表还是由 OS 处理，取决于架构（x86 硬件处理，MIPS 等由软件填充），这一点属于具体实现，不能一概而论。

## 一句话分界

这两个概念处在**不同层级**：

- **TLB Miss**：地址翻译的“缓存”没命中，但页很可能就在内存里。
- **缺页**：翻译结果查到了，但那个页**不在内存**。

资料里说得比较直接：TLB 命中时，CPU 直接用缓存中的物理页框号完成地址转换，不需要访问内存中的页表 [资料《tlb.md》#0]；而未命中时 CPU 仍需查询页表，**只有**页表项表明该页不在内存时才会触发缺页异常，因此 TLB Miss 不等于缺页 [资料《tlb.md》#1]。

## 因果链

​```
CPU 给虚拟地址
   │
   ├─ TLB 命中 ──────────────────→ 得到物理页框号，直接访存   [资料#0]
   │
   └─ TLB Miss
        │
        └─ 查页表（内存里的页表项）
             │
             ├─ 页表项有效（页在内存）→ 取页框号，填回 TLB → 继续执行
             │        ← 到这里就结束了，全程没有异常，也没有磁盘
             │
             └─ 页表项无效（页不在内存）
                      │
                      └─ 触发缺页异常 → 陷入内核，由操作系统处理     [资料#1]
​```

关键点：**TLB Miss 是一条必然经常发生的常规路径**，因为 TLB 很小，几乎每一步都可能 miss；而缺页是稀有事件，代价在磁盘级别。把两者混在一起，代价模型就完全错了。

## 你还不确定的部分：缺页处理与页面置换的边界

你之前的说法是「缺页就是要去磁盘把页读进来」。方向没错，但漏掉了两处边界。

**边界一：进入缺页异常后，第一步是判断合法性，尚不进行读盘。**

操作系统拿到出错地址后，先看这个地址是不是这段地址空间里合法的页：

- 非法（越界、无权限）：交给进程发信号终止，例如段错误，**根本不读盘**。
- 合法但不在内存：才进入装载流程。

**边界二：页面置换只是「没有空闲页框」时才走的分支，并非缺页处理的必经步骤。**

​```
缺页异常进入 OS
   │
   ├─ 地址非法 → 终止进程 / 报错          （没有磁盘 I/O）
   │
   └─ 合法但不在内存
        │
        ├─ 有空闲页框 ──────────────→ 直接分配
        │
        └─ 没有空闲页框
             │
             └─ 页面置换：选一个牺牲页
                  ├─ 脏页 → 先写回磁盘
                  └─ 干净页 → 直接丢弃
                       │
                       └─ 腾出页框
        │
        └─ 从磁盘把目标页读进这个页框
             │
             └─ 更新页表项（标记有效、填页框号）
                  │
                  └─ 返回，重新执行那条触发异常的指令
​```

所以准确的说法是：**缺页处理必然涉及“把页弄进内存”，但不必然涉及“换出某一页”**；换出只在内存已满时发生。

**这里最容易混淆的一对词**，值得单独记一下：

| | 换的是什么 | 发生在哪 | 代价 |
|---|---|---|---|
| TLB 替换 | TLB 里的一个**页表项缓存** | 每次 TLB Miss 装入新项时 | 极小 |
| 页面置换 | 内存里的一个**物理页框** | 缺页且无空闲页框时 | 磁盘级 |

两者名字都像“换”，但前者换的是缓存条目，后者换的是真正的内存内容。TLB Miss 导致的只是前者。

另外提醒一句：缺页处理完、更新了页表之后，如果之前存在与该页对应的旧 TLB 项，可能需要让它失效，否则会用到过时的翻译。具体由硬件自动完成还是由操作系统显式指令完成，不同架构做法不同；这点我给不出通用答案，得看你学的具体架构。

   │

   │
   ▼

   │
   ▼
返回用户态，重新执行那条出错的指令（这次能翻译成功了）

### 分界线在这里

**缺页 ≠ 置换。**

- 缺页是「**我要的页不在内存里**」——这是 MMU 查表查出来的事实。
- 置换是「**我没地方放它了**」——这是内核对物理内存紧张做出的应对。

如果此刻空闲页框列表里还有页框，整个缺页处理过程根本不会碰到任何一页别人正在用的页，也就完全不会发生置换。把这两件事绑定成一条流程，是这一步最常见的分叉点。

而一旦真走到置换，才会有「选谁当牺牲者、它脏不脏、脏的话要先写回磁盘、改它的页表项、必要时刷 TLB」这一整套动作——那是置换的开销，不是缺页本身的开销。

### 另外两个容易混进去的环节

1. **地址不合法或权限不够，也会以「页错误」的形式报告上来**，但内核在 ① 那一步就判定它是非法访问，走的是给进程发信号的路径，跟「从磁盘读页」毫无关系。异常名字一样，处理路径完全分岔。
2. **不是所有缺页都要「去磁盘读」**。比如匿名页首次访问，可能直接映射一个全零页，压根不用碰磁盘。所以「缺页 = 磁盘 I/O」只在部分场景成立，把它当成定义就会在这里出错。

### 用一个判断标准自查

> 看到一个缺页，先问：**这次是「页不在内存」，还是「内存里没位置」？**

前者是缺页处理，后者才引入置换。这一句能同时厘清流程边界，也能解释为什么「缺页次数」和「置换次数」是两个不同的计数。
