# TCP 三次握手：第三次 ACK 的作用

TCP 建立连接需要三次握手：客户端发送 SYN（携带初始序列号 client_isn），服务端回复 SYN-ACK（携带 server_isn 并确认 client_isn），客户端再发送 ACK（确认 server_isn）。

第三次握手不是多余的。它让服务端确认两件事：第一，客户端确实收到了 SYN-ACK，因而具备接收能力；第二，客户端确认了服务端的初始序列号。只有第三次 ACK 到达后，服务端才认为连接已建立。若缺少第三次握手，服务端无法区分“客户端没收到 SYN-ACK”和“客户端收到了但不想继续”，也无法确认客户端已经知道服务端的序列号，连接的两端状态会不一致。

第三次握手还可以避免历史重复 SYN 造成旧连接初始化。客户端最终发出的 ACK 把双方的序列号同步到同一个连接上下文里。
